แต่ละโปรเจกต์คือโฟลเดอร์หนึ่งที่ค่อยๆ โตขึ้นเมื่อมีข้อมูลใหม่เข้ามา `README.md` คือทางเข้าทางเดียว

## อะไรไปอยู่ที่ไหน

| เนื้อหา | ไปที่ |
|---|---|
| ภาพรวม สถานะ เดดไลน์ ขั้นต่อไป | `Projects/{name}/README.md` |
| โน้ตทำงานของ {Name} | `Projects/{name}/notes/{topic}.md` |
| ข้อมูลค้นคว้า | `Projects/{name}/research/{topic}.md` |
| บรีฟ สเปก ข้อกำหนด | `Projects/{name}/briefs/{name}.md` |
| ฉบับร่าง สคริปต์ งานเขียน | `Projects/{name}/drafts/{name}.md` |
| ไอเดีย | `Projects/{name}/ideas/{name}.md` |
| ฟีดแบ็ก | `Projects/{name}/feedback/{name}.md` |
| รูปภาพและสื่อ | `Projects/{name}/assets/` |
| ของเก่าจากโปรเจกต์นี้ | `Projects/{name}/archive/` |

ชื่อโฟลเดอร์เป็นตัวพิมพ์เล็ก คั่นด้วยขีด ไม่มีเลขนำหน้า (`research/` ไม่ใช่ `01-Research/`) ถ้าไม่มีโฟลเดอร์ไหนเหมาะ โปรเจกต์เพิ่มโฟลเดอร์ของตัวเองได้

## โครงของ README

1. บล็อกข้อมูล (ด้านล่าง) พร้อม `description`
2. `## คืออะไร`: หนึ่งหรือสองบรรทัด ลิงก์ไปที่ [[goals]]
3. `## สถานะและขั้นต่อไป`: ตอนนี้อยู่ตรงไหน และขั้นต่อไปคืออะไร
4. `## ทำงานอย่างไร`: ใส่เฉพาะเมื่อมีอะไรอัตโนมัติเขียนลงที่นี่ (งานตั้งเวลา สคริปต์)
5. `## อะไรอยู่ที่ไหน`: ใส่เฉพาะเมื่อมีโฟลเดอร์ย่อยแล้ว เป็นตารางเล็กๆ ลิงก์ไปแต่ละโฟลเดอร์

## บล็อกข้อมูล (frontmatter)

```yaml
---
type: notes
date: 2026-10-13
status: active
project: Website-Redesign
tags: [website-redesign, notes]
---
```

- `type`: `project` (คือ README ซึ่งมี `created`, `updated` และ `description` ด้วย), `notes`, `research`, `brief`, `draft`, `idea`, `feedback`, `plan`
- `status`: `active`, `paused` หรือ `done` สถานะของ README คือสถานะของโปรเจกต์
- `project`: ชื่อโฟลเดอร์ของโปรเจกต์
- `tags`: ชื่อโปรเจกต์ก่อน แล้วตามด้วยประเภท

## กฎ

- โปรเจกต์ใหม่มีแค่ `README.md` สร้างโฟลเดอร์ย่อยก็ต่อเมื่อมีเนื้อหาที่ต้องใช้ แล้วลิงก์ไว้จาก README
- README คือสารบัญ อย่าเขียนเนื้อหาของโฟลเดอร์ย่อยซ้ำไว้ในนั้น
- ไม่มี `CLAUDE.md` ในโปรเจกต์ กฎของโปรเจกต์เดียวไปอยู่ใน "กฎเฉพาะโปรเจกต์" ด้านล่าง
- ใส่ `project:` ในบล็อกข้อมูลของทุกโน้ตที่เกี่ยวข้อง
- โปรเจกต์ที่จบแล้วย้ายไป `Memory/archive/{name}/` ก็ต่อเมื่อ {Name} บอกเท่านั้น
- ทุกโปรเจกต์ควรช่วยให้ถึงเป้าหมายใน [[goals]] ตอนตรวจเช็ก ให้แจ้งเป้าหมายที่ไม่มีโปรเจกต์ และโปรเจกต์ที่ไม่มีเป้าหมาย
