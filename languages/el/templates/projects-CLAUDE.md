Κάθε έργο είναι ένας φάκελος που μεγαλώνει όσο έρχονται πληροφορίες. Όλα ξεκινούν από το `README.md`.

## Πού πάει τι

| Περιεχόμενο | Πάει στο |
|---|---|
| Γενική εικόνα, πού βρίσκεται, προθεσμία, επόμενα βήματα | `Projects/{name}/README.md` |
| Οι σημειώσεις εργασίας που κρατά {Name} | `Projects/{name}/notes/{topic}.md` |
| Έρευνα | `Projects/{name}/research/{topic}.md` |
| Οδηγίες, προδιαγραφές, απαιτήσεις | `Projects/{name}/briefs/{name}.md` |
| Πρόχειρα, σενάρια, κείμενα | `Projects/{name}/drafts/{name}.md` |
| Ιδέες | `Projects/{name}/ideas/{name}.md` |
| Σχόλια και κριτικές | `Projects/{name}/feedback/{name}.md` |
| Εικόνες και πολυμέσα | `Projects/{name}/assets/` |
| Παλιό υλικό από αυτό το έργο | `Projects/{name}/archive/` |

Τα ονόματα φακέλων είναι με πεζά και παύλες, χωρίς αριθμούς μπροστά (`research/`, όχι `01-Research/`). Ένα έργο μπορεί να έχει και δικό του φάκελο όταν κανένας από αυτούς δεν ταιριάζει.

## Πώς είναι στημένο το README

1. Μπλοκ πληροφοριών (πιο κάτω), με `description`.
2. `## Τι είναι`: μία ή δύο γραμμές, με σύνδεσμο προς το [[goals]].
3. `## Πού βρίσκεται και επόμενο βήμα`: πού βρίσκεται, το επόμενο βήμα.
4. `## Πώς τρέχει`: μόνο αν κάτι αυτόματο γράφει εδώ (μια προγραμματισμένη εργασία, ένα script).
5. `## Πού είναι τι`: μόνο όταν υπάρχουν υποφάκελοι. Ένας μικρός πίνακας με σύνδεσμο προς τον καθένα.

## Μπλοκ πληροφοριών (frontmatter)

```yaml
---
type: notes
date: 2026-10-13
status: active
project: Website-Redesign
tags: [website-redesign, notes]
---
```

- `type`: `project` (το README, που έχει επίσης `created`, `updated` και `description`), `notes`, `research`, `brief`, `draft`, `idea`, `feedback`, `plan`.
- `status`: `active`, `paused` ή `done`. Το status του README είναι το status του έργου.
- `project`: το όνομα του φακέλου του έργου.
- `tags`: το έργο, μετά το είδος.

## Κανόνες

- Ένα καινούργιο έργο είναι απλώς ένα `README.md`. Φτιάξε υποφακέλους μόνο όταν έρθει περιεχόμενο που τους χρειάζεται, και βάλε σύνδεσμο προς αυτούς από το README.
- Το README είναι το ευρετήριο. Μην επαναλαμβάνεις μέσα του το περιεχόμενο των υποφακέλων.
- Όχι `CLAUDE.md` μέσα σε έργο. Οι κανόνες για ένα μόνο έργο μπαίνουν στο «Κανόνες ανά έργο» πιο κάτω.
- Βάλε `project:` στο μπλοκ πληροφοριών κάθε σχετικής σημείωσης.
- Ένα έργο που τελείωσε πάει στο `Memory/archive/{name}/` μόνο όταν το πει {Name}.
- Κάθε έργο πρέπει να εξυπηρετεί έναν στόχο στο [[goals]]. Σε ένα τσεκάπ, επισήμανε στόχους χωρίς έργο και έργα χωρίς στόχο.
