# 繁體中文詞彙表（zh-TW）

## 稱呼

用「你」，不用「您」，就像台灣大多數消費型 App（LINE、Dcard、Apple 台灣）跟使用者說話的方式。整套內容都一樣：表單、訊息和規則檔（給 AI 代理的指示也用「你」）。{Name} 不用「他」或「她」：英文寫 "they" 的地方，改成再寫一次 {Name}，或把句子換個說法，這樣就不會弄錯性別。像 "Owner" 這種角色也用不分性別的說法（團隊表格裡寫「擁有者」）。

這套是用台灣的說法重新寫的，不是從簡體中文轉換字形：用「檔案、資料夾、軟體、網路、設定、訊息、專案、範本、匯入、行事曆、封存」，不用「文件、文件夾、軟件、網絡、設置、消息、項目、模板、導入、日曆、歸檔」。

標點用台灣的全形標點：，。、：；？！（）「」，引號裡面再有引號時用『』。中文和英文字母、數字、程式碼之間空一格（例如「用 {Language} 回覆」、「最多 3 個」）。不用破折號。

觸發語（使用者對 AI 代理說的話）用口語，像平常講話一樣（「幫我的大腦做健檢」），後面接英文原句。

## 主要資料夾

| 英文 | 繁體中文 |
|---|---|
| About | 關於我 |
| Daily | 日記 |
| Projects | 專案 |
| Relationships | 人脈 |
| Memory | 紀錄 |
| Library | 資源庫 |
| Skills | 技能 |

- **關於我**：台灣的網站和社群都這樣寫，一看就懂。
- **日記**：每天一篇，大家最熟悉的說法。
- **專案**：台灣的說法（不用「項目」）。
- **人脈**：比「關係」自然，「關係」聽起來像感情。
- **紀錄**：放決定、研究、申請和封存，是慢慢累積下來的東西。「記憶」太抽象。台灣慣用「紀錄」這個寫法。
- **資源庫**：放提示詞、範本和思考框架。「圖書館」太字面，「資料庫」在台灣是指 database。
- **技能**：AI 代理的應用程式在中文介面裡也這樣稱呼。

- **customers = 客群**，不是「客戶」：不然「關於我」裡會有 `客戶.md`，「人脈」裡又有 `客戶` 資料夾，很容易搞混。
- **Collaborators = 合作夥伴、Partners = 合作單位**：合作夥伴是一起創作的人，合作單位是媒體、場地、平台這類組織。
- **archive = 封存**：Gmail 和 Apple 台灣都用「封存」。
- **frameworks = 思考框架**：只寫「框架」太像程式用語。
- **queue = 待處理清單**：「佇列」太技術。
- **_Leads = _潛在客戶**：「Lead」不是每個人都懂。

## 範例

範例人物改成台灣常見的名字，整套都一樣：Ana Costa = 林安娜（簡稱安娜），Marta = 美玲（出版社編輯），João = 阿哲（工作室夥伴），Lia = 小莉（經紀人）。表單裡的地點是「台北，台灣」，不是 "Lisbon, Portugal"；範例網站是 "https://yoursite.tw"。

## 大括號裡的預留文字

真正的預留位置（`{Name}`、`{Language}`、`{person or company}`、`{weekday in English}` 等）一字不改。大括號裡如果是填寫說明，或 AI 代理要寫進筆記的範例文字（例如 `{用一句話說明這個檔案放什麼。}`），就翻成中文，這樣寫進筆記的內容才會是中文。
